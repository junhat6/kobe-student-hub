# Kobe Student Hub の記事を書く

Kobe Student Hub は、神戸電子の学生が学習・制作の経験を記事にして共有する場所です（学校公式ではありません）。
このスキルは、あなた（エージェント）が **本人の経験から** 記事の下書きファイルを作るための手順です。
できたファイルは本人がサイトの下書き画面（`/drafts` の「自分のAIエージェントと書く」）に読み込み、自分で読んで直してから公開します。

**あなたは投稿しません。** サイトに投稿する API はありません。ファイルを作るところまでがあなたの仕事です。

## 1. 材料を決める（最初に本人に聞く）

次のどれから書くかを本人に聞いてください。決まっていればそのまま進みます。

- A. 本人が話すこと・手元のメモ（Obsidian、Notion の書き出し、README など）
- B. 過去の AI エージェントとの作業履歴（下の手順 2）
- C. いまのリポジトリの git log・Issue・PR

## 2. 作業履歴から記事のネタを探す（B のとき）

作業履歴はこのコンピュータの中にあります。**外へ送らず、この端末の中だけで読んでください。**

| ツール | 場所 |
| --- | --- |
| Claude Code | `~/.claude/projects/<プロジェクト>/<セッション>.jsonl` |
| Codex | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`、依頼の一覧は `~/.codex/history.jsonl` |
| Gemini CLI | `~/.gemini/tmp/<プロジェクト>/chats/session-*.json` |
| Antigravity CLI | 依頼の一覧 `~/.gemini/antigravity-cli/history.jsonl`、成果物 `~/.gemini/antigravity-cli/brain/<id>/` |

そのまま開くと大きすぎるので、同梱のスクリプトで絞ります（Python 3 の標準ライブラリだけで動きます）。

```sh
# 一覧（日付・ツール・プロジェクト・タイトル）
python3 scripts/session_index.py index --since 2026-10-01
python3 scripts/session_index.py index --grep docker        # 依頼文に含む語で絞る
python3 scripts/session_index.py index --project my-app     # プロジェクト名で絞る
# 1セッションを短い会話録に（ツールの出力は省き、秘密らしき文字列とメール・ユーザー名を伏せる）
python3 scripts/session_index.py show <index に出たパス> --max-chars 20000
```

スクリプトが無い環境では、`/agent-kit/ksh-article/scripts/session_index.py` をサイトから取得するか、上の場所のファイルを `jq` などで「本人の依頼文」と「エージェントの返答の文章」だけに絞って読んでください。ツールの出力全体は読まないでください（長く、秘密が混ざりやすい）。

記事になりやすいのは次のような場面です。候補を **3〜5個**、1行ずつ「誰に・何がわかる記事か」を添えて本人に見せ、1つ選んでもらってください。

- 詰まって、試して、解決した（エラー → 原因 → 直し方 → なぜそうなるか）
- 2つの方法で迷って、理由をつけて決めた
- 初めて使った技術・ツールで「最初に知りたかったこと」
- 作ったものの「作る前と後」で変わったこと
- AI エージェントへの頼み方を変えたら結果が変わった

## 3. ログに無いことを本人に聞く

ログには「何をしたか」はあっても「なぜそう思ったか」「どう感じたか」はありません。書く前に 2〜3 問だけ聞いてください。

- そのとき一番困ったことは何か
- 同じ立場の後輩に一言いうなら何か
- いまならどうするか

本人の答えは、本人の言い回しをできるだけ残して本文に使います。

## 4. 書く

- 本人が実際にやったこと・確かめたことだけを書く。やっていない経験・数字・感想を作らない。わからないところは `（ここに〇〇を書く）` と空けておく。
- 読者は神戸電子の学生（1〜4年生）。専門用語は最初に一言で説明する。
- 長さは 1,500〜4,000 字くらい。見出しは `##` から。コードは言語名つきのコードブロック。
- HTML タグは表示されないので使わない。
- 画像は多めに入れる前提で書く（見出しごとに1枚以上が目安）。ファイルには画像を入れられないので、置きたい場所に `（写真：〇〇）` `（図：〇〇の比較）` と書いておく（本人があとでサイトで追加する）。使えるのは、本人が撮った写真・作ったものと、内容を図にした自作の図版だけ。ネットで見つけた画像・店の公式写真は使わない。AI が作った写真風の画像で、実在の店や料理を「その店のもの」に見せない。図版には「図：記事用に作成」と出どころを添える。
- 課題の解答の丸写しは載せない。考え方・詰まった点は書いてよい。
- お店のレビューなら：本人が実際に行った店だけ。行った時期を書き、値段・メニューは「その時点」と書く。無料提供・割引・依頼があれば本文に書く。店員や他の客を特定しない。

## 5. 公開してよいか確かめる（必ず）

このリポジトリやログには、記事に載せてはいけないものが混ざりがちです。下書きを渡す前に、自分で全文を見直して伏せてください。

- パスワード・API キー・トークン・`.env` の中身・秘密鍵
- メールアドレス（とくに学校のメール）、電話番号、住所
- 本人以外の人の名前・顔・アカウント名（本人が「出してよい」と言った人を除く）
- `/Users/<名前>/` のようなユーザー名入りのパス、社内・アルバイト先の非公開の情報、非公開リポジトリの名前
- 他の人の文章・画像の無断転載

見直した結果（伏せたもの・本人に確認したいもの）を、ファイルとは別に本人へ短く伝えてください。

## 6. ファイルを作る

次の形の Markdown ファイルを 1 つ作り、公開リポジトリの外（例：`~/ksh-drafts/<英数字の短い名前>.md`）に保存します。

```markdown
---
title: 記事のタイトル（200文字以内）
summary: 一覧に出る概要。何がわかる記事かを1〜3文で（300文字以内）
tags: [タグ1, タグ2]          # 5個まで、1個24文字以内
audience: 想定読者（200文字以内）
prerequisite: 前提知識（200文字以内、なければ「なし」）
outcome: 読んだあとにわかること・できること（200文字以内）
minutes: 6                    # 読むのにかかる分数
---

## 見出し

本文…
```

最後に本人へこう伝えてください。

> `~/ksh-drafts/〇〇.md` を作りました。Kobe Student Hub の「下書き」で新しい下書きを作り、「自分のAIエージェントと書く」→「.md ファイルを選ぶ」で読み込んでください。公開前に、自分の経験と違うところがないか読んで直してください。

## 記事を読むとき

Kobe Student Hub の記事ページには「AIに渡す」ボタンがあり、記事を Markdown でコピーできます。本人が記事を貼ってきたら、出典の URL と書いた人を示したうえで、本人のプロジェクトや状況に合わせて説明してください。記事の内容を本人の経験として書き写さないでください。
