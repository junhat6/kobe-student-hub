# 通常の下書きを本人が整理する

## 仮説と範囲

通常の下書き画面で本人が不要な保存版を整理できれば、私的な制作記録を安心して管理できるのではないか。PRDの私的な執筆・下書き再開を支える候補であり、学生価値の確認結果ではない。PRD原文は変更しない。

既存の`/drafts`と共有DELETE APIを使い、通常variantだけへ削除を接続する。新しいlab・本人限定試用・認証方式・保存先は作らない。既存の画面、配色、編集と保存の導線を継承する。公開停止・公開記事削除、アカウント削除、期限による自動削除は含めない。

## 受入条件

- 選択中の1件について保存タイトル・版、未保存の文章も失うこと、元に戻せないことを確認する。公開済みの記事は残ると明記する。取消ではDELETEを送らない。
- 確認中・送信中は対象や文章を変更せず、保存・作成・選択との競合を防ぐ。送信前にbufferを消さない。dirty・確認・pending・結果不明の移動警告を維持する。
- 現在の保存版を`expectedVersion`として1回だけ送信する。厳密な200 JSON `{deleted:true}`を確認した後だけ対象の一覧・選択・buffer・プレビュー・比較を消し、他の下書きを保持して一覧を再取得する。
- 404／409・通信／EOF／期限・不正応答を成功にしない。結果不明では手元の文章を保持し、保存・再削除・自動再送を止める。保存版を読めた場合にだけ、その版を明示的に基準にしてから再操作する。GET404や20件一覧からの不在だけで削除済みとは判断しない。
- 通信断などでsessionを確認できない間は、既存guardがbufferをメモリに保持して隠す。同一session再確認では確認・pending・不明状態とbufferを保持し、失効・変更が確認されたsessionでは旧状態・buffer・遅着ACKを破棄する。削除成功とは扱わない。共有APIのowner・CAS・Origin／CSRF・session／accountの最終SQL条件を変更しない。年度未登録・参加期間外のactive本人による整理は既存方針を維持する。
- 合成認証と実ローカルD1でHTTP・PC/mobile操作を確認し、所有server／browserを終了する。独立QA・CI前に完成と判定しない。実端末・実学校Google・実学生の価値確認とは区別する。

## 公開条件との境界

通常画面のaccount／authoring visibilityとOAuth／draft HTTPの4gateはfalseを維持する。fixtureは配備しない。実ログ、Google接続、remote schema、運営等の公開条件は別に満たす。この変更をログゲートの代替完成としない。削除後のバックアップ・platform logを含む消去保証も行わない。

既存の[通常下書き](ORDINARY-DRAFTS.md)と[私的保存](PRIVATE-DRAFTS.md)を使い、[撤去済み試用の削除](PRIVATE-DRAFT-DELETION.md)は履歴として区別する。

## 実装担当による確認

独立QAとCIは別担当の確認待ち。以下は実装担当のローカル結果で、独立QAの代替ではない。

| 確認 | 実行結果 |
| --- | --- |
| build、local DB初期化、deploy dry-run | 成功。remote操作なし |
| unit／実ローカルD1 | 77files・694tests成功、最終19.52秒 |
| 公開E2E | 最終62件成功、11.2秒 |
| 通常登録・下書きbrowser全体 | 66件成功。後の移動警告文への削除追記後は、通常下書き30件を再実行して成功 |
| 実commit後ACK欠落の追加readback | PC/mobileの2件成功。厳密なDELETE成功応答、本人の別GET404と一覧0件を確認してからACKを失わせ、UIは未確認を維持 |
| 既存共有エディタ | 保存・失敗・Markdown補助・sessionの4file、32件成功、50.0秒 |

新しいbrowser試験は7受入case×PC/mobileの14件。取消DELETE0、対象版と未保存文章の確認、pending中の入力／操作停止と移動取消、同session保持、版競合の再確認、実commit後のACK欠落と未確定のままのGET404、送信前の通信断からの明示回復、変更sessionへの遅着遮断、削除確定後の一覧取得失敗を扱う。新たなlabやfixture hookは加えていない。共有server・schema・4gateは不変。

最初のfocused browser実行は10成功・2失敗だった。通信断で既存guardが編集画面を隠す挙動に対し、試験が直ちに可視の不明状態を期待していた。同sessionの明示再確認を挟む試験に修正し、最終実行で文章と不明状態の保持を確認した。guardを緩める変更はしていない。

ChromiumのPC 1280px／mobile 390px viewportで確認・pending・結果不明の代表6画像を撮り、実装担当が全6枚を開いて確認した。画面全体の横overflowなし。合成認証・架空データであり、実Google・物理端末・実学生・本番削除の試験ではない。所有runnerとbrowser／子processを終了し、所有group残存0と8787／8788／8790の待受なしを確認した。

削除の厳密ACKを失った後、保存版が読めなければこのAPIだけで削除済みを証明できない。手元の文章はページメモリだけにあり、reloadや移動後の復元・バックアップ／ログ消去は保証しない。実ログ・Google接続などの公開条件は未完了のまま。
