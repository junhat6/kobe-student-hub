# 記事カード比較の準備 — H02

状態: 比較用プロトタイプと実施案を用意した段階。学生による価値検証は未実施。採用案・成果・需要を確定しない。

## 状況と仮説

新しい分野を学ぶ学生が、記事を選ぶ前に必要な前提知識と読後にわかることを短く把握できれば、自分に合う記事を選びやすくなるのではないか。PRDの前提知識の不一致という課題と、記事発見の体験に基づく。公開サービスの導線調査は着想であり、学生の価値の証明ではない。[Issue #5](https://github.com/junhat6/kobe-student-hub/issues/5)に元の検討を記録。

## 個人評価と学生試用の区別

PRDのE08（読む前に理解できそうか判断）、E23（読後に自分のPCで試す）、E24（空き時間で読む見通し）は発案者本人が採用した体験案である。個人の評価という一つの裏づけとして扱い、他の学生の検証済みとは扱わない。読む時間は短さだけでなく、長い記事の詳しさへの期待の手がかりにもなるという意見を保持する。

そのため読了時間表示はA/Bの両方で同じまま残す。短い記事を選ぶように誘導しない。サンプルの分数は比較用の仮の目安で実測値ではない。読後に試せそうなことが想像できたかも聞けるが、実践した価値まで確認済みとしない。

## 比較対象

- A: タイトル、要約、タグ、投稿者、更新日、読む時間。現行カード。
- B: Aと同じ情報に「読む前に知っておくこと」「読んだあとにわかること」を追加。

記事は同じ架空サンプル3件、並びも同じ。作品や推薦は比較に混ぜない。`/study/cards?variant=a` と `?variant=b` で直接表示できる。詳細本文は共通で、ブラウザの戻るで比較画面に復帰する。現在のホームのカードは変更しない。比較画面への入口は「このプレビューについて」にのみ置く。

Bは情報量とカードの高さが増える。内容の理解しやすさだけでなく、一覧を見渡す負担・読まれるまでのスクロールも観察する。Bが有利という前提で進行しない。

## 少人数の試用案

参加者・実施日時・実施する端末はまだ決めていない。参加は任意とし、学校の評価・成績と無関係で、途中でやめられることを説明する。録画、実名、学校メール、学籍番号、学力評価をこの比較のために集めない。運用や同意の確認が必要な記録方式は、実施前に確定する。

1. 最初に、今気になっていることや既に試したことを本人の言葉で短く聞く。能力を採点しない。
2. AまたはBの一方だけを示し、「いまの自分が読んでみたい記事を1つ選び、理由を教えてください」と伝える。前提知識欄を探すように誘導しない。
3. 読む前に「何がわかりそうか」「自分が知っていることだけで読めそうか」を聞く。迷う、読まない、別の題材がほしいという回答も受け入れる。
4. 本文を読み、「期待と違ったところ」「先に知りたかったこと」「選び直したいか」を聞く。正しい選択を採点しない。
5. もう一方を示して、選び方の違い・一覧の見やすさ・負担を聞く。表示順は参加者ごとにA→BとB→Aを入れ替える。2回目は既読になるため、順序効果と記憶の影響を残す。因果的なA/B試験と呼ばない。
6. どちらも役立たない、タイトルや要約だけで十分、テーマが合わないという結果も記録して次の仮説へ進む。

複数の学生がスマホで利用する場面を優先し、PCでの差も確認する案。人数・数値目標・成功閾値を未合意のまま作らない。

## 結果の記録枠

| 観点 | 記録すること |
| --- | --- |
| 条件 | 匿名セッション記号、表示順、画面幅/端末種別。個人を特定する組合せは避ける |
| 選択 | 選んだサンプル、選択理由、迷った点、選ばない理由 |
| 見通し | 読む前に期待した内容と、読後に感じた差 |
| 選び直し | 変更の有無と理由。変更が少ないほど良いと決めつけない |
| 負担 | 文字量、カードの高さ、スクロール、用語の分かりにくさ |
| 学び | 仮説を支える観察、反する観察、サンプル固有の問題、次に確かめること |

現在は全項目「未実施」。生の回答や個人情報をpublic GitHubへ投稿しない。必要な私的記録の保存場所・保持期間を事前に決め、公開する場合は合意した匿名の学びだけにする。

## 動作QAと判断の境界

AIのQAではA/B切替、URL再読込、同一サンプル/並び、追加情報、詳細と戻る、スマホのはみ出し・障害時表示を確認する。これでわかるのは画面が動くことだけ。学生が選びやすい・役立つという結論にはしない。

試用後に、欄を増やす、短くする、詳細だけに残す、何も変えない、別の題材で再確認する、のどれが妥当かを観察から判断する。エディターや推薦基盤はこの比較のために追加しない。


## E23の実践を観察する場合（任意・未実施）

カード比較の後、本人が記事を読んで試したいと希望し、専用の練習環境を使える場合に限って、既存計画の延長として「この記事を手がかりに、次に試したいことはありますか」と尋ねる。コピー操作やGit実行を先に指示せず、読まない・別の記事・環境がないという回答も受け入れる。新たな比較画面や回答収集機能は追加しない。

試す場合は個人の既存作業や学校の共有リポジトリを使わせず、合意した使い捨て環境とクリップボードで実施方法を先に確認する。編集して保存する工程に気づくか、コードをどう移すか、差分や結果をどう解釈するか、記事のどこが助け/妨げになるかを本人の言葉で聞く。実コマンド成功・コピークリック数を理解や価値の証明にしない。端末のクリップボード内容、認証、個人リポジトリ、実名や生のコマンド履歴を収集・公開しない。記録は既存計画の同意/私的保存条件へ従う。AIが用意した/tmp fixtureでのGit操作確認とは明確に区別し、学生による実施は現在も未実施。
