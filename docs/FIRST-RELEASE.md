# 最初の実ユーザー利用までの残条件

[公開 Issue #38](https://github.com/junhat6/kobe-student-hub/issues/38) と既存設計・QAの入口をまとめたものです。PRDを変更したり、未決定の規約・責任者・窓口を決めたりする文書ではありません。個別の検証範囲はリンク先を優先します。

## 現在の到達点

| 区分 | 確認できている範囲 | そこからは判断できないこと |
| --- | --- | --- |
| 実装・ローカル検証済み | 架空アカウントによる下書き、本人入力の公開プロフィール、保存版の明示初回公開、匿名の記事・投稿者・新着閲覧、通報受付・一時非公開・運営の読取専用確認、セッション切替と現在セッションのログアウト、記事いいね、画像なし独立作品の保存・明示公開・匿名作品一覧、作品通報の受付・限定運営の読取確認 | 実際の学校認証、在籍資格、通知到達、運営判断、実利用への同意 |
| 実接続で確認済み | 公開プレビューの架空サンプル閲覧。根拠は [QA-DEPLOYMENT.md](QA-DEPLOYMENT.md) と [QA-CODE-PRACTICE.md](QA-CODE-PRACTICE.md) の対象範囲 | ローカル試作の実サービス接続、一般ユーザーのログイン・投稿 |
| 外部設定・方針判断待ち | 下表の認証・資格・運営・プライバシー・配信条件 | 設定ファイル、テスト成功、受付記録だけで実運用完了とは扱わない |
| 利用者・端末検証待ち | 学生による試用と物理端末での確認 | AIの動作QAやPC／モバイル幅のエミュレーションは、その代わりにならない |

## 実ユーザー接続前のゲート

「必要な証拠」は既存条件の確認方法であり、取得済みという意味ではありません。実ユーザーの認証・投稿を開く前に、対象の接続に関係する未完了条件を解消します。

| ゲート／現状 | 完了判断に必要な証拠 | 次の具体的な作業・参照 |
| --- | --- | --- |
| 学校Google認証・ブラウザ接続：部品とローカル試験あり、実接続未完了 | 登録したリダイレクト先、サーバーでの交換・署名検証、一回限りの試行、PKCE・ブラウザ結合、失敗・再送・期限・並行操作の検証。実コントローラーでCookie・CSRF・ログアウトまで確認 | 許可された専用設定を用意し、実経路を接続・独立QA。[GOOGLE-LOGIN.md](GOOGLE-LOGIN.md)、[OAUTH-ATTEMPTS.md](OAUTH-ATTEMPTS.md)、[SESSION-LIFECYCLE.md](SESSION-LIFECYCLE.md) |
| 在籍・卒業・アカウント回復：判断待ち | 現役学生の書込資格、年度境界・補正、卒業後の修正／削除と本人確認の決定、サーバー側の許可・拒否例 | 学校ドメインやactive状態だけで資格を確定しない。未決定のケースを決めてから接続。[AUTH-BOUNDARY.md](AUTH-BOUNDARY.md)、[DECISIONS.md](DECISIONS.md) |
| 私的データと公開操作：ローカル旅程あり、実接続未完了 | 他人の下書きへの拒否、競合・通信失敗でも文章を保護、確認した保存版と本人入力プロフィールだけの公開、私的識別子の非公開。実セッション切替後の境界も確認 | 実認証の下で編集・プロフィール・公開・匿名閲覧を一続きに検証。プロフィールの修正／削除と実際の同意・規約は別途整理。[PRIVATE-DRAFTS.md](PRIVATE-DRAFTS.md)、[PUBLIC-PROFILE.md](PUBLIC-PROFILE.md)、[PUBLICATION-JOURNEY.md](PUBLICATION-JOURNEY.md)、[本人の公開記録](OWN-PUBLICATION-RECORDS.md)。保存上の状態確認は理由説明・通知・異議対応の完成ではない |

| 運営・通知：読取専用試作あり、実担当・配送未接続 | 限定した実運営権限、失効、理由付き判断・監査、通知の送信・到達・失敗・再送の記録 | 責任を持つ運営と非公開の通知先・方式を決め、実配送を検証。受付やpending記録を送信成功と表示しない。[MODERATION-JOURNEY.md](MODERATION-JOURNEY.md) |
| 復元・削除・異議・問い合わせ：方針待ち | 復元後の再通報、保持／消去、本人への安全な説明、異議受付・所有者確認・返答の実導線 | 既存の判断表に沿って決定する。宛先や保持期間を推測せず、状態だけ戻す復元を実装しない。[MODERATION-JOURNEY.md](MODERATION-JOURNEY.md) |
| ログ・配信・キャッシュ：実利用の保護ゲート未完了 | 実経路の各ログ層で必要な秘密情報を保護した範囲の証拠。非公開／削除後の新規記事・一覧・関連表示・キャッシュからの除外 | [LOGGING-GATE.md](LOGGING-GATE.md) を完了してから実callbackを接続。設定やサンプルでの未観測を保護の証明にしない。既に受信した内容の消去とは区別する |

| 実環境データと運用：接続前確認が必要 | 対象・差分・既存データ保持を確認した変更手順、バックアップ・保持と障害／問い合わせ対応。配信とデータ変更を分けた検証 | [DEPLOYMENT.md](DEPLOYMENT.md) に従い、必要なデータ変更を個別に確認する。デプロイ成功をスキーマや運用の完了扱いにしない |

## 学生・実端末で確かめること

[既存の小人数試用計画](CARD-STUDY.md) を使い、読む前の見通し、記事選択、活動への理解、次に試したい行動を本人の言葉で確かめます。役立たない・選ばないという観察も残し、機能を増やすこと自体を成功にしません。参加条件、同意、私的記録の保存・保持を整理し、生の回答や個人情報は公開Issueへ載せません。

物理PC・スマートフォンでは、実際のブラウザ・認証・入力・画面遷移・必要なコピー操作を確認します。実IME、Cookie、端末固有の動作をエミュレーションの結果から推定しません。学生価値と端末動作は別々に記録します。

## 再開するとき

未完了ゲートのうち次の一つを選び、必要な外部設定／判断、実装、独立QA、証拠、次の判断を [WORK.md](WORK.md) と Issue #38 へ対応づけます。実接続の証拠は対象範囲と限界を明示し、設定・認証情報・生ログ等の私的運用情報はこの公開文書へ転記しません。未決定を埋めるためだけの機能追加や、架空の成功表示は行いません。
