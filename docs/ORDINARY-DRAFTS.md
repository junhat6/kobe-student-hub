# 通常アプリで下書きを書き、保存・再開する

## 仮説と範囲

学校Googleで登録した学生が、本体のアカウントから下書きへ進み、スマホ／PCで同じ保存版を再開できれば、検証用ページを探さず知識・経験の共有準備を進められるのではないか。PRDのE14・E15・E17を支える接続で、利用価値や離脱率の改善はまだ確認していない。原文は変更しない。

既存の下書き保存・20件一覧・再開・Markdown編集・プレビュー・版競合の回復と、既存のセッション境界を通常の`/drafts`へ接続する。新しいlab、本人限定試用、認証方式や保存先は作らない。通常画面からの公開はこの単位に含めず、下書きが本人用であることと公開の未提供を示す。

## 受入条件

- 本体アカウント→下書き→作成→明示保存→再読込・再開がつながる。未ログイン時はログイン／登録へ進め、catalog障害はこの私的画面を止めない。
- 既存の保存と競合復帰を使い、保存失敗や結果不明で文章を消さない。作成・保存の通信中と未保存の入力があるとき、通常リンクやBack／Forwardでの移動を確認し、キャンセルすれば編集中の画面を保持する。reload／closeにもブラウザ標準の警告を使う。
- 同じセッションの再確認ではページ内入力を保持し、変更されたセッションには前の下書き・遅い応答を引き継がない。本人・CSRF・在学期間・最終SQLの既存チェックを弱めない。文面やtokenをURL／browser storageへ保存しない。
- 本体entryで使う通常HTTP compositionを既存の合成認証環境でも使う。fixture用identity・fault hookを本体へ移さない。通常のfrontend visibility、OAuthと下書きのsource gateはすべてfalseを維持する。runtime入力だけで開かない。
- 実装者と別contextのQAでsource／HTTP境界とPC/mobile操作・画像を確認し、通常check・green CIの後にmainへ統合する。エミュレーションと合成認証は、実端末・学校Google・学生価値の検証と区別する。

## 実公開との境界

この接続だけで、一般ログイン・投稿を有効化しない。実ログ、専用Google設定、remote schema、運営・問い合わせ等の[FIRST-RELEASE](FIRST-RELEASE.md)条件は残る。設定・権限・credential・契約・remote SQLの変更を含めず、サンプル専用の公開境界を維持する。通常の下書き削除は[本人整理の別単位](ORDINARY-DRAFT-DELETION.md)で接続し、記事公開への接続は後続で扱う。
