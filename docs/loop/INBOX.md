# オーナーの受け口 — 送り先はメール1本

2026-11-22 作成。オーナー（服部）が動作確認で見つけたもの（スクショ・画面収録・一言・記事の材料）を、
スマホだけでも Mac からでも、迷わず agent に渡し、結果を同じ場所で受け取るための仕組みです。
agent が毎回読む指示書は [prompts/inbox.md](prompts/inbox.md)、部品は `scripts/loop/inbox.mjs`。

## 結論

- **送り先は、Gmail の受け口アドレス（本人の Gmail に `+ksh` を付けたもの）だけ。** bot・セッション・skill のどれに渡すかをオーナーが選ぶ必要はない。中身が不具合でも、材料でも、質問でも同じ宛先。
- **返事は、送ったメールと同じスレッドに未読で届く。** Issue を作ったら番号と URL、材料なら editor に渡したこと、質問なら答え。修正が本番に出たら、同じスレッドにもう一度「直った」と届く。
- **受け取りは常時動いている Mac mini の Orca automation `ksh inbox`（10分ごと）。** 届いていなければ agent は起きない（precheck で Gmail を見るだけ）。送ってから返事まではおおむね 10〜40 分。

## オーナーの操作

### はじめに1回だけ

1. iPhone の連絡先に「ksh」を作り、メールに受け口アドレス（Gmail のアドレスの `@` の前に `+ksh`）を入れる。以後は宛先欄に `ksh` と打てば候補に出る。
2. （任意）Gmail で `ksh-受付済` ラベルを左のメニューに出しておくと、やりとりの一覧になる。

### 出先・スマホだけ（MacBook Air が無くてよい）

1. スクショを撮る（画面収録でもよい）。
2. 写真の左下の共有 → **Gmail**（またはメール）→ 宛先に `ksh` → 本文に一言（「投稿ボタンが押せない」「この文が長い」など）→ 送信。件名は空でも、適当でもよい。
3. 返事は Gmail の受信トレイに、同じスレッドで未読として上がる。違っていたら、そのスレッドに返信すれば続きとして受け取る。

### MacBook Air から

- スクショ（⌘⇧4）や画面収録を、Gmail の新規メールにドラッグして `ksh` 宛てに送る。Finder のファイルなら右クリック → 共有 → メール でもよい。手順と返事の届き方はスマホと同じ。

### 送ってよいもの

| 送ったもの | agent がすること | 返事 |
| --- | --- | --- |
| 画面・挙動のスクショ／収録＋一言 | 同じ画面を同じ幅で開いて再現を試し、既存の Issue に足すか新しい Issue を作る（重さで P0〜P2）。直すのは finish | 「#N を作りました」＋再現したか＋いつ頃本番に出るか。直ったらもう一度届く |
| 記事の材料（体験のメモ・写真） | 本人の言葉のまま editor の材料置き場へ。次の editor（09:15・21:15）が下書きにする | 「材料として受け取りました」 |
| 質問・方針・指示 | 答える。方針を変えるなら DECISIONS に残す | 答え |

1通に複数のことを書いてよい。複数の画面なら1通に何枚添付してもよい（25MB を超える動画は Gmail が Drive のリンクに変える。それも読む）。

## 仕組み

```text
iPhone / MacBook Air ──メール（自分の Gmail から受け口アドレスへ）──▶ Gmail
                                                                        │
Mac mini：Orca automation `ksh inbox`（*/10 * * * *）                  │
  precheck: inbox.mjs count … 受け取り待ち・直った知らせ待ちが 0 なら起こさない
  agent   : inbox.mjs pull → 画像を見る・再現 → Issue / 材料 / 答え
            inbox.mjs reply  → 同じスレッドへ返事（未読）＋ `ksh-受付済` ＋ Issue を控える
            inbox.mjs followups / notify → 控えた Issue が閉じて本番に出たら「直った」
                                                                        │
iPhone の Gmail ◀──────────────── 同じスレッドに未読で返事 ─────────────┘
```

- 宛先とアカウントは公開リポジトリに置かず、Mac mini の `~/.config/kobe-student-hub/inbox.json` に置く。
- 落とした添付・本文・控え（どのスレッドがどの Issue か）は `~/.config/kobe-student-hub/inbox/` にだけ置く。
- **受け取るのは、オーナーの Gmail アカウントから送ったメールだけ**（Gmail の `SENT` ラベルが付いたもの）。他人が受け口アドレスを知って送っても `SENT` は付かないので読まない。From の偽装では `SENT` は付けられない。
- agent の返事は本文末尾に印（`KSHBOT`）を入れ、送った直後に `ksh-受付済` を付けるので、自分の返事を新しい依頼と取り違えない。

## なぜこの形か

**メールを選んだ理由。** 出先のスマホで、写真アプリから追加のアプリ無しに数タップで送れて、返事も同じアプリの同じスレッドで読める経路は、メールが一番短い。Mac からも、別の Mac からも同じ宛先で済む。Mac mini では `gog` がすでに Gmail を読み書きでき、常時動いている。

**採らなかった形と理由。**

| 案 | 採らない理由 |
| --- | --- |
| GitHub Issue に直接スクショを貼る | リポジトリが公開。実機の画面にはアカウント・下書き・利用者名が写りうる（恒久条件「非公開の利用者フィードバックを公開 Issue に書かない」）。非公開の置き場を別に作ると送り先が増え、写真から送る手数もメールより多い（アプリで Issue を開いて添付する） |
| Orca の bot / Home Chat | bot は Mac mini の Orca の中にあり、出先のスマホから届かない。bot を使わない判断は [ORCA.md](ORCA.md#2-orca-bots-を使わない理由ソースで確かめたこと) |
| Claude のアプリや Remote Control でセッションに話しかける | どのセッションに送るかをオーナーが選ぶことになる（今回の困りごとそのもの）。セッションは周回ごとに捨てるので、結果が後から追えない |
| 共有フォルダ（iCloud Drive・Google Drive）に置く | 置いた後に「受け取ったか」「どうなったか」が返ってこない。返事の場所が別に要る |
| AirDrop | Mac が手元に無いと使えない（今回の困りごと） |

**採らない場合の影響。** 受け口が決まっていないと、オーナーは毎回「どこに渡すか」を考え、出先で見つけたことはメモに残らないまま忘れられる。実機（スマホ）でしか分からない不具合は AI の巡回では見つからない（viewport ≠ 実機）ので、ここが細いと 11-24 以降の実利用で最初に壊れるところが見えなくなる。

## 限界と見直す条件

- 返事はオーナー自身のアドレスから届くため、Gmail アプリの**プッシュ通知が鳴らないことがある**。受信トレイの未読と `ksh-受付済` ラベルで見る。通知が要るとなったら、iOS の「VIP」に自分を入れる、または返事の経路を足すことを考える。
- Mac mini と Orca が止まっていると受け取らない（メールは Gmail に残るので、動き出せば受け取る）。garden の点検で `ksh inbox` の最新 run を見る。
- 1回に受け取るのは5件まで。残りは10分後の回で受け取る。
- 学校の Google アカウントなど**別のアカウントから送ったものは受け取らない**。必要になったら `inbox.json` と `SENT` の判定を見直す。
