# UX巡回の採点基準と利用者の旅

patrol ループが毎回これを読み、旅を実際に歩いて採点します。基準は人が較正して育てます（較正の記録は末尾）。

## 誰のためのサービスか（巡回者が忘れてはいけない前提）

神戸電子の学生が、先輩や同級生の **記事・作品から知識・経験・活動に出会い、次の行動の材料にする** 場所。
友だち探しアプリでも、学校の情報ポータルでもない。学校公式ではない。

巡回者は次の3人になりきって歩きます。

| 人物 | 状況 | 期待 |
| --- | --- | --- |
| **新入生ミナ** | 1年生。授業でGitを習ったばかり。スマホで、昼休みの5分で見る | 自分でも読める記事が見つかる。誰が書いたか分かる |
| **2年生ソウタ** | ゲーム制作中。作品を見せたいが文章は苦手。PCで作業 | 作品をすぐ載せられる。記事を書くなら途中保存できる |
| **運営者** | 通報メールを受けた。PCで、短時間で判断したい | 何が起きたか一画面で分かり、迷わず判断できる |

## 情報設計の原則（オーナー方針 2026-11-22）

画面を見るとき・直すときは、次を「好み」ではなく基準として扱います。迷ったらこちらを優先します。

1. **文字は少なく。** 説明文を足して分かりやすくするのではなく、説明が要らない形に直す。
2. **アイコンで言えることはアイコンで。** 例：「コピー」「コピーしました」の文字ではなく、コピーのアイコンと完了のチェックのアイコン。公開＝地球、非公開＝錠、編集＝鉛筆、履歴＝時計。アイコンだけのボタンにも支援技術向けの名前（`aria-label`）と `title` を必ず付ける（見た目の文字を減らすのであって、読み上げの情報は減らさない）。
3. **文字で説明しないと伝わらないと感じたら、設計を疑う。** 利用者が知っておく必要のある情報を減らす方向で作り直す（例：「年度は4月から翌年3月まで」と説明する代わりに「2025年4月 → 2027年3月」と選ばせる）。
4. **利用者にとって意味のない操作・表示は消す。** 「保存状態を確認」「再読み込み」のように、システムの都合で利用者に確認させているボタンは置かない。画面が自分で読み直す。失敗したときだけ「もう一度」を出す。
5. **当たり前の順番は、案内文ではなく画面の形で示す。** 例：公開プロフィールが無いうちは、マイページはプロフィールを作る画面になり、書く画面は「まずプロフィールをつくろう」だけを出す。
6. **成功は静かに、失敗ははっきり。** 成功の文言は読み上げ用（`role="status"` の `sr-only`）とチェックのアイコンで足り、失敗だけを見える文字で出す。
7. **独自の型を作る前に、学生が普段使うメジャーなサービスの型を探す（キメラ）。** 学生が毎日使う X・Instagram・YouTube・note・Zenn・Qiita・GitHub・Google などに同じ役目の画面があれば、その型（置き場所・アイコン・操作の順番）に寄せ、複数のサービスから部分ごとに借りてよい。使い方を既に知っているので、説明も学習も要らない（原則1・3の近道）。借りるのは**形**であって**決まり**ではない：公開範囲・本人確認・閲覧履歴は本人専用・通報の運営などの恒久条件は借り先に合わせて緩めない。目的（記事・作品から人へ）に反する仕組み（フォロー数・ランキング・DM・閲覧数の公開・通知でせかす）は、型がメジャーでも借りない。借りた先は commit 本文か Issue に1語で書く（例：「型: YouTube の履歴」）。

### 見比べる型（原則7の当てはめ、2026-11-22 時点）

画面を直す・新しく作る前に、まずこの表の型と見比べる。表に無い画面は、同じ役目のメジャーなサービスを探してから作り、ここに1行足す。

| 画面・部品 | 寄せる型 | 主に借りる所 |
| --- | --- | --- |
| プロフィール `/students/:id`・マイページ | GitHub のプロフィール＋Instagram/X | 左にアイコン・名前・自己紹介、右に固定（ピン留め）と草、「プロフィールを編集」は自分のときだけ同じ画面に出る |
| ヘッダー | note・Zenn | 右上に検索・「書く」・アバターのメニュー。お知らせはベル＋未読の点 |
| 記事 `/articles/:id` の操作 | note・Zenn・Qiita | 本文の後にハート（数つき）・共有（X・リンクのコピー）・「…」。PC では本文の左に縦に並べて追従 |
| 通報 | X・YouTube | 常設の欄ではなく「…」→「通報」→ダイアログで理由を選ぶ |
| 下書き・記事を書く `/drafts` | Zenn・note のエディタ | 一覧（下書き／公開中のタブ）と、タイトル大・本文だけの全画面エディタ。右上に保存の状態と「公開する」、タグ・概要は公開の手前のパネル |
| 画像を添える | note・Zenn | 本文への貼り付け・ドラッグ＆ドロップ、ツールバーの画像アイコン |
| タグの入力 | Qiita・Zenn | 1つずつチップになり、候補が出る入力（カンマ区切りの説明を要らなくする） |
| 公開の停止 | YouTube Studio・note | 自分の記事の「…」→「非公開にする」＋確認ダイアログ1回 |
| 閲覧履歴 `/history` | YouTube・Chrome の履歴 | 日付ごとの見出し、行ごとの ×、「履歴を一時停止」トグルと「すべて削除」を横に。説明段落と「再読み込み」は置かない |
| 検索 `/search` | YouTube・Zenn | 上に検索欄、結果は「すべて／記事／作品」のタブ、タグはチップ |
| 作品の登録 `/works/new` | 記事のエディタと同じ型（GitHub のリポジトリ作成の項目の少なさ） | 名前・説明・リンク・画像だけで始め、ほかは後から |
| 確認・取り消し | Gmail・Google ドライブ | 消すときはダイアログより「元に戻す」付きのトースト（取り消せる操作に限る） |
| 卒業・在学期間 | LinkedIn の学歴 | 「2025年4月 → 2027年3月」の期間で選ぶ（実装済み） |

借りないもの：フォロー／フォロワー数、ランキング、DM、閲覧数の公開、プッシュ・メールで連続をせかす通知（目的と恒久条件に反するため。2026-11-22 の DECISIONS を参照）。

## 旅（journey）

各旅は PC（1280×800）とモバイル（390×844）の両方で歩きます。手順は目安で、迷った場所こそが所見です。

| ID | 旅 | 人物 | 環境 | 完了の条件 |
| --- | --- | --- | --- | --- |
| J1 | トップ → 「Git」で検索 → 記事を選ぶ → 前提を見て読む → 投稿者のプロフィール → その人の別の記事か作品へ | ミナ | 本番（匿名）＋ローカル | 3分以内、迷わずに投稿者の別の活動へ着ける |
| J2 | 学校Googleで登録 → 年度を申告 → プロフィール作成 → 記事を下書き → 画像を貼る → 別ブラウザで続きを書く → 公開 → 公開画面で確認 → 改稿 | ソウタ | ローカル `editor:preview`（架空アカウント） | 書いた内容を一度も失わず、公開URLを人に送れる状態になる |
| J3 | 作品を投稿 → 既存の自分の記事を紐づける → 公開 → トップと自分のプロフィールに出ることを確認 | ソウタ | ローカル | 作品から記事へ、記事から作品へ行き来できる |
| J4 | ログインして記事を3本読む → 1本にいいね → 履歴を見る → 1件消す → 全部消す | ミナ | ローカル | 履歴が自分だけのものだと分かり、消したものが戻らない |
| J5 | 別の3アカウントで1記事を通報 → 一時非表示を確認 → 運営画面で判断 → 投稿者側で結果を確認 | 運営者 | ローカル | 運営者が3分以内に判断でき、投稿者が何が起きたか分かる |
| J0 | 異常系：存在しないURL、APIを止めた状態、通信断、ログイン切れで書きかけ | 全員 | ローカル | どの状態でも戻り道がある（行き止まりがない） |

**本番では J1、J0 の一部（存在しないURL・ログイン切れ）、オーナーのアカウントでログインして歩ける部分（J2 の登録後〜下書き・別ブラウザで続き、J4 の閲覧履歴の確認と削除）。** 公開・いいね・通報・運営の判断はローカルだけ（他の利用者に見える・届くため）。ログインはオーナーのアカウントだけで、ログイン後の画面は公開 Issue に貼らない。実在の学生の非公開データは、確かめる必要があるときだけ開く（LOOPS.md の「本番での禁止」、2026-11-23 DECISIONS）。

## 重大度

| 重大度 | 定義 | 例 | 扱い |
| --- | --- | --- | --- |
| **S1 止まる** | 旅を最後まで行けない、内容が失われる、非公開のものが見える | 公開ボタンが反応しない、下書きが消える、他人の下書きが見える | P0 Issue。リリース列車を止める |
| **S2 迷う** | 行けるが、普通の学生なら諦めるか誤解する | 次に何を押すか分からない、エラーの意味が分からない、モバイルで操作対象が隠れる | P1 Issue |
| **S3 引っかかる** | 行けるし分かるが、余計な手間や違和感がある | 文言が硬い・内部用語、余白の崩れ、読み込みが遅い | P2 Issue（1回3件まで） |

## 観点（各旅で必ず見る）

1. **完遂**：旅を最後まで行けたか。どこで何回迷ったか。
2. **次の一手**：どの画面でも「次に何をすればよいか」が1つ目で分かるか。行き止まり（戻る以外の行き先がない画面）はないか。
3. **言葉**：学生が普段使う言葉か。開発の内部用語（ordinary、pending、snapshot、gate、moderation など）や英語が画面に出ていないか。**文字の量**：説明文・注意書きが、上の「情報設計の原則」に照らして多すぎないか。消しても困らない文・ボタンは所見にする。 **型**：同じ役目のメジャーなサービスの型（原則7・「見比べる型」）から外れた独自の置き場所・操作になっていないか。外れていたら、寄せる先を所見に書く。
4. **失わない**：入力したものがエラー・ページ移動・ログイン切れで消えないか。
5. **見える化**：公開／非公開、保存済み／未保存、サンプル／実投稿の状態が、色だけに頼らず分かるか（アイコン＋支援技術向けの名前でよい。長い文で説明していないか）。
6. **モバイル**：390pxで横にはみ出さない、操作対象が小さすぎない、キーボードが入力欄を隠さない。
7. **アクセシビリティ**：axe の critical/serious が0、キーボードだけで旅を完了できる、focus が見える。
8. **速さ**：トップと記事でモバイル相当の LCP が 2.5秒以内（ローカル計測は目安）。
9. **嘘をつかない**：未実装の機能が動くように見えない、数字（いいね数・人気）を捏造していない。
10. **目的との一致**：記事・作品が主役で、そこから人へつながっているか。学生一覧が主役になっていないか。
11. **楽しさ（また来たくなるか）**：空状態・公開した後・積み上がりの画面が、草・お祝いと同じトーン（丸み・暖色 `--warm` と草の緑・小さな動き）で「ここで何かが育つ」と感じられるか。素っ気ない文字だけの空状態や、出した直後に何も起きない画面は S3 の所見にする。ただし読みやすさ・原則1（文字は少なく）・`prefers-reduced-motion` を崩さず、演出は装飾（`aria-hidden`）にとどめる。数を競わせる・連続をせかす仕掛けは楽しさに数えない（DECISIONS 2026-11-22「続けたくなる体験」）。

## 所見の書き方（Issue）

```text
タイトル: [S2][J2][モバイル] 下書きの保存状態が画面外にあり、保存されたか分からない

旅/手順: J2 の手順4。390×844、ローカル editor:preview、main <sha7>
起きたこと: 本文入力後、保存状態の表示がスクロール外にあり、…
期待: 入力欄の近くで「保存済み」が分かる
証拠: (スクリーンショット)
観点: 5 見える化
```

- 1所見＝1Issue。同じ原因の所見はまとめる。既存Issueと同じなら新規にせずコメントで「再現した（SHA）」と書く。
- 直し方の案は書いてよいが、決めつけない。直すのは builder。
- スクリーンショットは公開画面か架空データのものだけ。

## 合否（巡回1回の結論）

- **不合格**：S1 が1件でもある。または、どれか1つの旅を完遂できない。
- **合格**：S1 が0件、全旅を完遂。S2 の件数を patrol log に記録する。
- 総合点は付けない。点数に丸めると、重大な1件が軽い多数に埋もれるため。

人が patrol の採点をブラインドで採点し直した結果と、それで直した観点をここに追記します（1行ずつ）。

- 2026-11-22 オーナー：マイページの「保存状態を確認」「再読み込み」は不要、年度の表し方が分かりにくい、文字が多い、公開プロフィールの作成をもっと当たり前に。→「情報設計の原則」を足し、観点3・5を直した。
- 2026-11-22 オーナー：プロフィール系に限らず、学生が普段使うメジャーなサービスの型で済むところはアプリ全体でキメラにする。→ 原則7と「見比べる型」を足し、観点3に「型」を足した。
- 2026-11-24 オーナー方針（#224）：アプリ全体を少しポップに、続けたくなる体験に。→ 観点11「楽しさ」を足し、空状態（ホーム・作品・探す）に芽のマークを入れた。
- 2026-11-24 オーナー動画フィードバック：空状態の芽のイラストは好評。一方で「探す／作品」の見出しサイズ差、「＋新しい下書き」の色違い、履歴の「自分だけに表示」と「履歴を残す」トグルの誤解、ログアウトの browser confirm、プロフィール画像の左ずれと枠線の弱さ、「公開中」タブがマイページに飛ぶ遷移、パンくずの不在を指摘。→ 統一感・誤解防止・階層の一貫性を基準に反映（#268〜#273）。
