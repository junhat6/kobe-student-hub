# UX巡回の採点基準と利用者の旅

patrol ループが毎回これを読み、旅を実際に歩いて採点します。基準は人が較正して育てます（較正の記録は末尾）。

## 誰のためのサービスか（巡回者が忘れてはいけない前提）

神戸電子の学生が、先輩や同級生の **記事・作品から知識・経験・活動に出会い、次の行動の材料にする** 場所。
友だち探しアプリでも、学校の情報ポータルでもない。学校公式ではない。

巡回者は次の3人になりきって歩きます。

| 人物 | 状況 | 期待 |
| --- | --- | --- |
| **新入生ミナ** | 1年生。授業でGitを習ったばかり。スマホで、昼休みの5分で見る | 自分でも読める記事が見つかる。誰が書いたか分かる |
| **2年生ソウタ** | ゲーム制作中。作品を見せたいが文章は苦手。PCで作業 | 作品をすぐ載せられる。記事を書くなら途中保存できる |
| **運営者** | 通報メールを受けた。PCで、短時間で判断したい | 何が起きたか一画面で分かり、迷わず判断できる |

## 旅（journey）

各旅は PC（1280×800）とモバイル（390×844）の両方で歩きます。手順は目安で、迷った場所こそが所見です。

| ID | 旅 | 人物 | 環境 | 完了の条件 |
| --- | --- | --- | --- | --- |
| J1 | トップ → 「Git」で検索 → 記事を選ぶ → 前提を見て読む → 投稿者のプロフィール → その人の別の記事か作品へ | ミナ | 本番（匿名）＋ローカル | 3分以内、迷わずに投稿者の別の活動へ着ける |
| J2 | 学校Googleで登録 → 年度を申告 → プロフィール作成 → 記事を下書き → 画像を貼る → 別ブラウザで続きを書く → 公開 → 公開画面で確認 → 改稿 | ソウタ | ローカル `editor:preview`（架空アカウント） | 書いた内容を一度も失わず、公開URLを人に送れる状態になる |
| J3 | 作品を投稿 → 既存の自分の記事を紐づける → 公開 → トップと自分のプロフィールに出ることを確認 | ソウタ | ローカル | 作品から記事へ、記事から作品へ行き来できる |
| J4 | ログインして記事を3本読む → 1本にいいね → 履歴を見る → 1件消す → 全部消す | ミナ | ローカル | 履歴が自分だけのものだと分かり、消したものが戻らない |
| J5 | 別の3アカウントで1記事を通報 → 一時非表示を確認 → 運営画面で判断 → 投稿者側で結果を確認 | 運営者 | ローカル | 運営者が3分以内に判断でき、投稿者が何が起きたか分かる |
| J0 | 異常系：存在しないURL、APIを止めた状態、通信断、ログイン切れで書きかけ | 全員 | ローカル | どの状態でも戻り道がある（行き止まりがない） |

**本番では J1 と J0 の一部（存在しないURL）だけ。** 本番で投稿・いいね・通報・ログインをしない。実在の学生のデータを開かない。

## 重大度

| 重大度 | 定義 | 例 | 扱い |
| --- | --- | --- | --- |
| **S1 止まる** | 旅を最後まで行けない、内容が失われる、非公開のものが見える | 公開ボタンが反応しない、下書きが消える、他人の下書きが見える | P0 Issue。リリース列車を止める |
| **S2 迷う** | 行けるが、普通の学生なら諦めるか誤解する | 次に何を押すか分からない、エラーの意味が分からない、モバイルで操作対象が隠れる | P1 Issue |
| **S3 引っかかる** | 行けるし分かるが、余計な手間や違和感がある | 文言が硬い・内部用語、余白の崩れ、読み込みが遅い | P2 Issue（1回3件まで） |

## 観点（各旅で必ず見る）

1. **完遂**：旅を最後まで行けたか。どこで何回迷ったか。
2. **次の一手**：どの画面でも「次に何をすればよいか」が1つ目で分かるか。行き止まり（戻る以外の行き先がない画面）はないか。
3. **言葉**：学生が普段使う言葉か。開発の内部用語（ordinary、pending、snapshot、gate、moderation など）や英語が画面に出ていないか。
4. **失わない**：入力したものがエラー・ページ移動・ログイン切れで消えないか。
5. **見える化**：公開／非公開、保存済み／未保存、サンプル／実投稿の状態が、色だけでなく文字で分かるか。
6. **モバイル**：390pxで横にはみ出さない、操作対象が小さすぎない、キーボードが入力欄を隠さない。
7. **アクセシビリティ**：axe の critical/serious が0、キーボードだけで旅を完了できる、focus が見える。
8. **速さ**：トップと記事でモバイル相当の LCP が 2.5秒以内（ローカル計測は目安）。
9. **嘘をつかない**：未実装の機能が動くように見えない、数字（いいね数・人気）を捏造していない。
10. **目的との一致**：記事・作品が主役で、そこから人へつながっているか。学生一覧が主役になっていないか。

## 所見の書き方（Issue）

```text
タイトル: [S2][J2][モバイル] 下書きの保存状態が画面外にあり、保存されたか分からない

旅/手順: J2 の手順4。390×844、ローカル editor:preview、main <sha7>
起きたこと: 本文入力後、保存状態の表示がスクロール外にあり、…
期待: 入力欄の近くで「保存済み」が分かる
証拠: (スクリーンショット)
観点: 5 見える化
```

- 1所見＝1Issue。同じ原因の所見はまとめる。既存Issueと同じなら新規にせずコメントで「再現した（SHA）」と書く。
- 直し方の案は書いてよいが、決めつけない。直すのは builder。
- スクリーンショットは公開画面か架空データのものだけ。

## 合否（巡回1回の結論）

- **不合格**：S1 が1件でもある。または、どれか1つの旅を完遂できない。
- **合格**：S1 が0件、全旅を完遂。S2 の件数を patrol log に記録する。
- 総合点は付けない。点数に丸めると、重大な1件が軽い多数に埋もれるため。
